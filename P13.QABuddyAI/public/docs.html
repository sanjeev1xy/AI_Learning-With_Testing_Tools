What is QABuddy.ai?

QABuddy.ai is an AI-powered assistant for QA engineers that provides cited answers grounded in your team's actual QA knowledge base — Selenium framework code, Playwright tests, test cases, JIRA tickets, PRDs, Jenkins logs, meeting transcripts, and glossaries.

Unlike generic AI chatbots that hallucinate, QABuddy retrieves the most relevant chunks from your indexed knowledge base using hybrid dense + sparse search, then passes them as grounded context to the LLM. Every answer includes numbered citations pointing back to the exact source.

Key capabilities:

  • Answer mode — practical QA engineering answers with code examples
  • Generate mode — auto-detected when you ask to create/write test cases
  • Source scoping — restrict retrieval to any subset of the 9 knowledge sources
  • Full transparency — per-answer view of rewrites, dense/sparse hits, RRF fusion and rerank scores

Architecture Overview

The system consists of two main pipelines:

Ingestion Pipeline (build-time)

  1. Parse — load raw files (PDF, CSV, JSON, Java, TypeScript, Markdown, logs)
  2. Clean — normalize whitespace, strip ANSI codes, deduplicate
  3. Chunk — split per source type (code 1200 chars / docs 1000 / logs 2000, with overlap)
  4. Embed — generate dense (semantic) + sparse (lexical) vectors via BGE-M3
  5. Index — upsert to Qdrant vector DB with metadata (source_type, source_id, citation, path)

Ingestion is idempotent per source: re-ingesting a folder first deletes its old points (deterministic UUID5 point ids), other sources stay untouched.

Query Pipeline (runtime)

  1. Query — user submits question via chat UI
  2. Mode detection — regex patterns classify intent (answer / generate)
  3. Rewrite — Groq generates alternate phrasings (3 search variants)
  4. Hybrid search — dense vector + sparse lexical search per variant (Qdrant)
  5. RRF Fusion — Reciprocal Rank Fusion combines both result lists
  6. Rerank — cross-encoder (bge-reranker-v2-m3) keeps top-6 chunks
  7. Cited answer — chunks injected as numbered context, Groq answers with [n] citations

Each indexed chunk carries the following payload:

# Qdrant point payload for every chunk:
{
  "text":        "[header]\n<chunk body>",   # what the LLM sees & cites
  "source_type": "code",                    # one of 6 types
  "source_name": "Selenium framework",
  "source_id":   1,                         # data-folder number (sidebar filter)
  "citation":    "BasePage.java:42",       # file:line, ticket, page or build
  ...                                       # per-source extras (ticket_key, tc_id, build_id)
}

Hybrid Retrieval

Retrieval runs two searches per query variant over the same Qdrant collection: dense (1024-dim BGE-M3 vectors, cosine) for meaning, and sparse (BGE-M3 lexical weights) for exact keywords — ids, exceptions, method names.

Reciprocal Rank Fusion

# RRF score for chunk d across both ranked lists:
score(d) = Σ 1 / (k + ranklist(d))

# Parameters:
k = 60   # dampens the head of each list

Cross-encoder rerank

# Top fused candidates re-scored against the ORIGINAL question:
scores = reranker.compute_score([question, chunk_text])
# keeps top-6 chunks; only these reach the LLM

The rewrite step widens recall (3 phrasings hit different vocabulary), RRF merges without score calibration, and the reranker restores precision before generation.

LLM & Prompt Engineering

The prompt system auto-detects the query mode and builds mode-specific system prompts:

ModeTrigger PatternSystem Behavior
answer(default)Practical answer grounded in retrieved chunks
generategenerate | create | write | draftStructured test cases with all required fields

All modes enforce the same core rules:

  • Answer only from provided context chunks — no hallucination
  • Cite every claim with [n] referencing the chunk number
  • If not in context, say so explicitly

Mode can also be forced from the sidebar dropdown (auto-detect / answer / generate).

API Endpoints

POST /api/chat

Chat endpoint. Accepts a question plus optional source scoping and mode override. Returns the full pipeline result as JSON.

// Request body
{
  "question": "Why is the checkout coupon test flaky?",
  "source_ids": [1, 4, 10],   // optional — sidebar checkboxes
  "mode": "answer"              // optional — omit for auto-detect
}

// Response (abridged)
{
  "answer": "... [1] ... [2]",
  "mode": "answer",
  "rewrites": [...],
  "citations": [{ "n": 1, "badge": "Jenkins", "citation": "BUILD-4521 console.log", ... }],
  "total_tokens": 1843,
  "debug": { "dense_top": [...], "sparse_top": [...], "rrf_top": [...], "rerank_top": [...] }
}
GET /api/status

Health / index status. Returns total chunks and per-source counts for the sidebar.

{ "exists": true, "points_count": 189,
  "sources": [{ "id": 1, "name": "Selenium framework", "count": 59 }, ...],
  "by_source": { "code": 139, "test_case": 40, ... } }

Run Locally

# 1. Create a virtualenv and install dependencies
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 2. Set environment variables
copy .env.example .env          # then put your GROQ_API_KEY inside

# 3. Ingest the knowledge base (first run downloads BGE-M3, ~2GB)
python ingest.py --source all

# 4. Start the app
python app.py                   # serves on http://127.0.0.1:5080

Extending the Knowledge Base

Drop new files into the matching data/ folder, then re-ingest just that source:

# e.g. new JIRA exports into data/04_jira_tickets/
python ingest.py --source 4

# chunk + report without touching the index
python ingest.py --source 4 --dry-run

Re-ingestion replaces only that folder's points (delete-by-source_id, deterministic ids), so the rest of the index is untouched. No re-embedding of other sources required.

Original Design (AITesterBlueprint3x)

QABuddy.ai is adapted from chapter_08_QABuddyAI in the PramodDutta/AITesterBlueprint3x repository by Pramod Dutta.

This local version implements the full original stack:

  • BGE-M3 embeddings — BAAI/bge-m3 model for dense + sparse vectors
  • Qdrant — vector database, embedded file-backed or server mode
  • Flask backend — Python web server
  • Groq API — openai/gpt-oss-120b model for generation
  • Hybrid retrieval — RRF fusion of dense + sparse Qdrant search results
  • Cross-encoder rerank — BAAI/bge-reranker-v2-m3
