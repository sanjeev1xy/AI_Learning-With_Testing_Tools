Bug Title: Cart total shows $0.00 after applying discount code when cart has 3+ items
Bug ID: VWO-48
Reporter: manual_tester_jane
Status: Open
Jira Priority (as filed): High
Components: Checkout, Pricing
URL: https://bugzz.atlassian.net/browse/VWO-48

Environment: Production, Chrome 120, Windows 11
Severity (Reporter): High

Steps to Reproduce:
1. Add 3 or more items to the shopping cart (subtotal > $50).
2. Apply discount code "SAVE20" (20% off the order).
3. Observe the cart total in the order summary panel.

Actual Result:
Cart total displays "$0.00" instead of the discounted amount. The user cannot
tell what they will be charged. Proceeding to the payment step still shows
$0.00 in the summary.

Expected Result:
Cart total should show the original subtotal minus 20% (e.g. subtotal $60.00 ->
total $48.00), matching the value returned by the pricing API.

Additional Info:
- Happens only when the cart has 3 or more items.
- Works correctly with 1-2 items (discount applies, total is right).
- Started after last Friday's deployment (v2.4.1). Was fine on v2.4.0.
- No errors in the browser console.
- The pricing API response (POST /api/v3/cart/price) shows the CORRECT
  discounted amount in its JSON body; only the on-screen total is wrong.
- Removing one item so the cart drops to 2 items makes the correct total appear
  again immediately, without re-applying the code.
- Reproduced on 5/5 attempts. Also reproduced by a second tester on Firefox 121.
